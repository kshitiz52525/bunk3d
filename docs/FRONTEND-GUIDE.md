# Frontend build guide (read after CLAUDE.md)

We are in the **frontend phase**: every screen is built against the mock API. Backend and database come later and plug into the same contract. Several people build different domains in parallel, so stay inside your files.

## Read first
1. `CLAUDE.md` (rules, owner decisions) and `HANDOFF.md` (spec). Business rules there are binding.
2. For each screen you own: `python3 tools/dump-screen.py <ScreenId>` (e.g. `T1-Feed`) prints the screen's markup with styles; read the `renderVals()` script too (states, sample data) with `sed -n '/class Component/,$p' design/screens/<id>.dc.html`. Look at `design/screenshots/mobile/<id>.png` (web consoles: `design/screenshots/web/`). The `.dc.html` is the spec for layout, copy and states, not code to port.
3. `S1-States` (`tools/dump-screen.py S1-States`): the empty / error / offline / loading / blocked states. Every list you build needs loading, error, empty (with one button) and offline handling. Use `StateCard`, `ErrorState`, `EmptyState`, `OfflineBanner`, `SkeletonList` from `@bunk3d/ui/native`.

## Non-negotiable
- Copy screen text exactly. Build every state: every `sc-if` branch and S1.
- Never reproduce prototype-only things: `dc-import` / `bk-ov` overlays (use real routes and `router.push` / `router.back()`), `Preview:` / `Simulate` / `(demo)` buttons, sample props, fixed 390x844 sizing.
- Dark only. No emoji anywhere in UI or code. Never white text on lime (use `color.onLime`). Hot pink at most once per view. Touch targets >= 44px, a label on every icon button, `aria-hidden` on decorative things.
- No invented numbers. Anything numeric in the UI comes from the API; the mock produces it from clearly flagged **seed** data (`seed: true`) or from real logic. Never promise earnings. Money is never computed in a screen: the API returns paise amounts (use `formatPaise` from `@bunk3d/core` for display only); the mock computes with `@bunk3d/core` (`computeTakeHome`, `priceTicket`, `ticketRefundPaise`).
- Respect product rules: anonymous only if `anonUnlocked`, stories never anonymous, clubs never anonymous, ID photos staff-only, phone/email/DOB never shown, no ranking of people, Spark is not dating, exact location never shown, Swap has no payments.

## Structure and where things go
- **Screens (mobile)**: Expo Router files in `apps/mobile/src/app/`. Tab bodies are `app/(vibe)/{tea,study,poppin,crew,discover}.tsx` and `app/(hustle)/{gigs,my-work,swap,bag}.tsx` (currently `TabPlaceholder`; replace the whole file). Everything else is a **root route** (`app/post/[id].tsx`, `app/event/[id].tsx`, ...), so it pushes over the tabs and Back returns to the caller. Never hard-code a Back destination; use `router.back()`. Never navigate with `replace` unless the screen must not be returned to.
- **Tab screens** pad their scroll content with `useHeaderSpace()` (top) and `useTabBarSpace()` (bottom), and pass `useChrome().onScroll` with `scrollEventThrottle={16}` so header and tab bar hide on scroll (M3-Motion).
- **Feature code**: `apps/mobile/src/features/<domain>/` for components, hooks, helpers. Shared primitives: `@bunk3d/ui/native` (`Text, Button, Chip, Card, Sticker, Input, Banner, Skeleton, Icon, Screen, StepHeader, IconButton, H1, PrimaryCta, TextLink, Spacer, state components, TabBar`). If you need a primitive that does not exist, build it in your own feature folder; do not edit shared UI files except where stated below.
- **Icons**: add yours in `packages/ui/src/native/icons/<your-domain>.ts` (path data; see `base.ts`). Do not edit `base.ts` or `Icon.tsx`. Names must be unique across files; prefix with your domain if unsure.
- **Fonts**: `Unbounded_800ExtraBold` (display, numbers), `Inter_500Medium`, `Inter_600SemiBold`, `Inter_800ExtraBold`. Tokens: `import { color, radius, space } from '@bunk3d/ui'`.
- **API**: screens only call `useApi().<domain>.<method>()` wrapped in `useAsync` (loading / error / ready) or call it in handlers. Never import from `@bunk3d/api/src/mock`. You own, for your domain: `packages/api/src/contract/<domain>.ts` (types + the `<Domain>Api` interface, with a comment per method stating who may call it and what RLS must enforce), `packages/api/src/mock/<domain>.ts` (+ optional `seed-<domain>.ts`), and tests in `packages/api/test/<domain>.test.ts`. Mock slices get a `MockCtx` (`wait`, `now`, `getSession`, `requireUser`, `profile`). Keep per-domain state in the slice's closure. Do not edit `contract/identity.ts`, `contract/index.ts`, `mock/index.ts`, `mock/identity.ts` or `mock/ctx.ts`; if you truly need something there, say so in your report instead.
- Pure rules (gates, voting, scoring, validation) go in `packages/core/src/<name>.ts` with tests in `packages/core/test/`, exported from `packages/core/src/index.ts` by adding one `export *` line at the end of that file.
- **Dependencies are preinstalled**: expo-camera, expo-video, expo-location, expo-document-picker, expo-image-picker, react-native-maps (no web support: provide a `.web.tsx` fallback), expo-clipboard, expo-haptics, expo-sharing, react-native-qrcode-svg, async-storage, expo-image, react-native-svg. Do NOT run `pnpm install` or add dependencies; if one is truly needed, report it. Do not run git commands that change history; the lead commits.
- **Web consoles** (`apps/web`): Next.js App Router, `'use client'` pages using `@bunk3d/api` hooks via the existing `Providers`. Each console has its own folder `src/app/<console>/` with a `layout.tsx` (uses `ConsoleShell` from `src/components/kit.tsx`; extend its `nav`). The kit has `PageHead, Card, Stat, Badge, Btn, Table, Loading, ErrorBox, Empty`. Console-specific components go under `src/app/<console>/_components/`. Console mock slices must not call `ctx.requireUser()` (console auth arrives in the backend phase).

## Verify your work (required)
- Typecheck and lint what you touch: `pnpm --filter @bunk3d/mobile typecheck`, `pnpm --filter @bunk3d/mobile lint`, `pnpm --filter @bunk3d/api typecheck`, `pnpm --filter @bunk3d/api test`, `pnpm --filter @bunk3d/core test` (web: `pnpm --filter @bunk3d/web typecheck lint build`). Other people's in-progress files may show errors; fix only your own.
- Run it for real. Mobile on web: `cd apps/mobile && CI=1 npx expo start --web --port <YOUR PORT>` (ports: Tea 8101, Study/Poppin 8102, Crew/DMs 8103, Discover/You/Safety 8104, Hustle 8105, Web A 3101, Web B 3102; for web consoles use `pnpm --filter @bunk3d/web exec next dev -p <port>`). Drive it with Playwright in headless Chromium: `npm i playwright-core` inside your scratchpad directory, launch with `executablePath: process.env.HOME + '/Library/Caches/ms-playwright/chromium-1248/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing'`, viewport 390x844, listen for `pageerror` and console `error`/`warning`. Sign in through the real flow: "I already have an account", any 10-digit number, code `123456` (returning user, wave 4, lands on `/tea`), or deep-link to your route after signing in. Screenshot each screen and each state and compare against `design/screenshots`. The dev console must be free of errors and warnings.
- Test your domain logic with unit tests (vitest). Rules that must be tested are named in `CLAUDE.md` and `HANDOFF.md`.
